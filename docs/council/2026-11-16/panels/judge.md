## First two minutes and scorecards

### HostShare — strong implementation, obscured developer benefit
- **Front door: weak-to-moderate.** README:3 identifies the driver; :5–28 immediately becomes default-IRQ/errno/HA proof. A judge must infer the compelling benefit: change a host-side data/config file and read it in QNX without rebuilding/transferring another image. README:30–74 offers commands, then extensive history rather than a concise use case.
- **Substance: strong, bounded.** native/qnx_hostshare.c:27–52 submits actual descriptor-backed DMA and waits for IRQ pulses; :91–120 negotiates virtio, maps physical memory, attaches interrupt, exchanges 9P; native/hostshare_mount.h:24–47,49–77 implements real QNX opens/reads/directory replies/EROFS. core/protocol.c:16–62 validates frames, lengths, tags and supported 9P messages. Not just a Python mock. Read-only, fixed f0test mount tag (:90), fixed /mnt/host mount (:100 in mount header), 16 path components (:31), 4000-byte reads (:53), regular files/directories only (:40): a useful bounded prototype, not a general filesystem.
- **Usefulness/innovation: strong utility, novelty unestablished.** Native QNX host-folder integration is a persuasive low-level result. No evidence here establishes first/unique/faster than alternatives. Explain who benefits and the existing serial-transfer/rebuild friction, without invented benchmark comparisons.
- **Evidence: strong within limits.** docs/acceptance/recording-20261115/RESULT.md:24–39 records seven independent checksums, denied write, changed host file visible, pending-read ESRCH and fresh remount. Its handler explicitly sleeps BEFORE RPC/DMA (native/hostshare_mount.h:56–59); this does NOT prove active-DMA crash safety. Historical EIO-only raw failures remain failures. git diff 44a2ffc3fdcd9a6de035d10f6bff134504826b1d HEAD -- core native returned empty, supporting unchanged native source, not a new execution.
- **Reproducibility: moderate-to-weak.** Licensed artifacts/toolchain needed. docs/RUN_NATIVE.md:24–49 now allows independently judge-built stock pinning, a useful advance. README quickstart still knowingly exits1 on historical --midread EIO assertion (:66–70), so a successful current contract looks failed without reading another document.
- **Highest-upside substantive change:** a genuinely usable **developer handoff mode**, configurable validated export tag/mountpoint and a narrow host-config-update → normal guest application consumption workflow, with clear errors and no write support. **NEEDS OLLY APPROVAL**: expands product/native interface and needs newly authorized native validation. Keep f0test historical path/pins intact. Acceptance: new legally provisioned stock route, fresh source/ELF/image binding, normal app sees two host versions without image rebuild, writes still rejected, invalid tag/mount cleanly refused, server death produces the documented bounded error and fresh-remount recovery. Do not promise automation/production security/active-DMA recovery.
- **Recommendation:** first make the existing benefit unmistakable; then approve this narrowly scoped usability feature rather than write support or broad HA. Write-capable 9P is the ambitious alternative (high effort/high corruption/permissions/crash-consistency risk); defer until a robust read-only product is independently repeatable.
